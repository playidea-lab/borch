Saving, and the Python route

Checkpoints are safetensors, not pickle. The Python borch, numpy and the Hugging Face tools all read the same bytes — a format only we could read would throw away half the point.

Save and load

save takes a record of named tensors and returns bytes; load takes the bytes back. Nothing touches the filesystem — in a browser there isn't one, so what you get is an ArrayBuffer you can download, put in IndexedDB, or hand straight back to load.

The same kernels, from Python

borch_webgpu is a binding that runs on top of borch.ts inside Pyodide. What it hides is exactly the four differences you met in the first lesson — await init(), awaited reads, .call(), and half of scope(). The result reads like the textbook code it is imitating.

The first run of this block loads Pyodide, which takes a few seconds. After that it is instant.

Training, in Python

One line more than the textbook: with torch.scope():. Everything else is the loop you already know. Compare the losses with lesson 4 — they are the same numbers, because underneath they are the same WGSL.

Where to go next. The playground gives you the same runtime with a bigger editor, a loss curve and the GPU counters. The API reference lists every exported name with the torch name it answers to. What is not here — CUDA, pretrained weights, mixed precision, distributed training — is listed on the home page, and the list is deliberately long.
