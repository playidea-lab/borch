Workbench

작업대: 올리고, 학습하고, 검수하고, 가져간다

브라우저 안의 marimo 노트북이다 — 반응형 셀, 표와 버튼 같은 UI 요소, 그리고 자기 키를 넣는 AI 조수가 딸려 있다. 첫 셀이 pyborch 를 싣고, 나머지는 한 번의 검수 작업이다: 이미지 업로드 → 이 탭의 GPU 에서 학습 → 모델이 의심하는 라벨부터 보이는 검수 표 → torch.onnx.export. 모델 경로는 둘이다: 동결한 ImageNet EfficientNet-B0 위의 선형 헤드(torch.hub.load, 이미지당 특징 벡터 하나, 수백 장이면 된다) 또는 처음부터 학습하는 소형 CNN. 아무것도 설치하지 않는다. zip에 images/와 masks/가 있으면 세그멘테이션 작업이 된다: U-Net이 마스크로 학습하고, 검수 표는 받은 마스크와 모델 마스크를 나란히 어긋난 순서로 보여 주며, 내보내는 것은 U-Net이다. 같은 노트북 GPU에서 재면 여기의 학습 한 스텝은 torch의 1.5배쯤이고, 이미지는 탭 밖으로 나가지 않는다.

노트북과 어떻게 다른가

  • 반응형. 셀 하나를 바꾸면 그에 딸린 셀만 다시 돈다. 검수 표에서 행을 고르면 아래 셀이 따라온다.
  • UI 요소. 파일 업로드, 표, 버튼이 Python 값이 된다 — 위젯 코드 없이.
  • AI 조수. 설정에 자기 API 키를 넣으면 셀 생성·오류 고침 제안이 된다. 코드와 오류만 나가고 이미지는 나가지 않는다.
  • 같은 wheel. import borch_webgpu as torch 가 여기서도 borch.ts 를 띄운다.

알아 둘 것

  • 열고 10초쯤 커널이 뜬다(Pyodide 와 marimo 를 받는 시간). 셀은 자동 실행되지 않으니 오른쪽 아래 실행 버튼을 누른다.
  • 라벨은 파일명의 첫 _ 앞부분이다. 아무것도 올리지 않으면 합성 3클래스로 돈다. 일을 하는 두 호출은 라이브러리 것이다. torch.decode_images가 파일을 이름에서 읽은 라벨과 함께 NCHW 배치로 만들고, (torch.ImageFiles는 같은 일을 필요할 때만 한다 — 수천 장의 zip 폴더를 배치마다 풀고 폴더명을 라벨로), torch.suspects가 모델 특징 공간에서 가장 가까운 이웃 다섯 개 중 라벨이 다른 비율로 각 라벨을 점수화한다 — 검수 표의 정렬 기준이다.
  • 검수 순서가 진짜 오라벨을 찾는가? CIFAR-10N 5만 장(사람이 실제로 붙인 라벨과 정답 라벨이 둘 다 있는 데이터)으로 바로 이 경로(동결 B0 pre-logits → torch.suspects)를 쟀다: 라벨의 9%가 틀린 세트에서 큐의 첫 20장 중 65%가 오라벨(무작위면 9%), AUROC 0.948, 큐의 18%만 보면 오라벨의 90%를 잡는다. 40%가 틀린 세트에서는 첫 20장 전부가 오라벨. 브라우저 경로는 5,000장 부분집합에서 네이티브와 몇 점 차이(AUROC 0.929 대 0.917). 어려운 세트가 한계를 말해 준다: CIFAR-100N(미세 100클래스, 40% 오라벨)은 AUROC 0.842, 큐의 첫 100장 중 78%가 오라벨; Food-101N(웹 수집 음식, 18% 오라벨, 틀린 것은 비슷하게 생긴 다른 음식)은 AUROC 0.767, 첫 20장 중 65% — 무작위의 두 배이지 일곱 배는 아니다. 규모가 크면 이웃을 늘려야 한다: 5만 장에서 k=20이 CIFAR-100N 주입 10%의 AUROC를 0.913에서 0.962로 올렸고, 워크벤치는 2,000장부터 20을 쓴다. 도메인 세트 셋에 정답 라벨의 10%를 뒤집어 넣었을 때(k=20): NEU-CLS 강판 표면 결함은 AUROC 1.000에 큐의 첫 20장이 전부 오라벨, ISIC 2019 피부경 0.920, PatchCamelyon 조직 패치 0.918 — 검사 카메라류 사진은 동결 백본이 제자리이고, 조직 사진부터 부분 미세조정이 필요해진다. 수는 전부 tests/review_eval.py에 있다.
  • 세그멘테이션도 같은 두 질문. Kvasir-SEG(내시경 1,000장, 용종 마스크, 96px)에 3단 U-Net을 올리고 학습 마스크의 1/5을 망가뜨렸다 — 다른 이미지의 마스크로 바꾸거나 용종에서 밀어냈다. 정답 마스크 대비 홀드아웃 IoU: 깨끗한 마스크로 학습하면 torch 0.55, 브라우저 0.51–0.57(하루 동안의 커널 버전에 따라); 마스크 1/5을 망가뜨리면 torch는 seed 여섯에서 0.40–0.50, 브라우저 0.46(오염 마스크 위 30에폭의 수치는 합산 순서에 따라 움직여 범위로 적는다). 800장×30에폭이 맥 GPU에서 34초(torch 20초) — 이틀 전엔 104초였고, GPU 타임스탬프로 재면서 커널을 하루 손본 결과다(BatchNorm 통계, conv 타일과 gather, 브로드캐스트 접기, cat, BatchNorm과 ReLU 짝짓기, 손실 함수 한 커널). 배치 16 한 스텝은 18 ms, torch는 12 ms. GPU가 실제로 쓰는 15 ms 중 9 ms가 conv — 채널이 작은 층은 직접 커널로 돌고, 가중치 그래디언트 GEMM이 가장 큰 항목이다. 마스크에는 투표할 이웃이 없어 큐는 모델 자신의 불일치(자기 마스크와 받은 마스크의 1−IoU)로 세운다: AUROC torch 0.88–0.93(seed별), 브라우저 0.91, 큐의 1/3쯤을 보면 틀린 마스크의 90%를 잡는다. tests/seg_eval.py·tests/browser/seg_eval_py.py.
  • 마지막 셀은 지원 보고다: torch.report()가 어댑터·검증 오류·메모리·버전과 이번 실행의 사실을 report.json 하나로 모으고, 이상(소프트웨어 래스터라이저, 오류, 장치 손실)이 있으면 말로 적는다.
  • 같은 노트북이 아무것도 못 내보내는 망을 위해 폴더 하나로 나온다: python3 site/build_bundle.py가 Pyodide·marimo 패키지·백본을 페이지 옆에 미러하고(75 MB), 검사가 바깥 요청을 전부 막은 채 눌러 본다.
  • 탭의 메모리와 Pyodide 의 패키지 범위 안에서 돈다 — 노트북 페이지의 목록과 같다.
